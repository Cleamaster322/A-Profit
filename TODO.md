### [~] Хранение файлов протоколов: папки «В работе» и «Завершённые»
- **Статус:** код и автотесты готовы. Осталось: применить миграцию 0016 на MySQL, запустить `relocate_protocol_files`, проверить вручную (см. «Проверка»).
- **Зачем:** в продакшене файлы протокола (DOCX, фото, будущие документы) должны лежать в папке с номером протокола. Пока протокол не утверждён — в «В работе», после утверждения — в «Завершённые». Сейчас всё лежит в `media/protocol_photos` и `media/generated_protocols`.
- **Где:**
  - новая модель настроек (одна запись) и её админка — `main/cars/models.py`, `main/cars/admin.py`;
  - новый модуль `main/cars/services/protocol_storage.py` — путь к папке протокола и к фото, перенос папки;
  - фото: `create/update/delete_protocol_photo`, `build_protocol_photo_path`, `delete_photo_file_if_exists` в `main/cars/views.py`;
  - статусы: `approve_protocol`, `return_protocol_to_draft`, `delete_protocol` в `main/cars/views.py`; `clear_protocol_data` в `main/cars/admin.py`;
  - DOCX: `main/cars/services/protocol_docx_generator.py`, `get_photo_path` в `main/cars/services/protocol_docx/context.py`;
  - выдача фото: `ProtocolPhotoSerializer.get_file_url` в `main/cars/serializers.py`, новый адрес в `main/cars/urls.py`, показ фото в `car_front/src/Features/ProtocolInspection/ProtocolInspectionPhotos.jsx`;
  - новая команда `main/cars/management/commands/relocate_protocol_files.py`.
- **Решения:**
  - Два пути задаются в админке. При сохранении проверяем: путь абсолютный, папки не совпадают и не лежат одна в другой, папка создаётся и в неё можно писать. Сетевые пути `\\сервер\...` допустимы. Пока пути пустые, используются `media/protocols/in_progress` и `media/protocols/completed`.
  - Структура: `<корень>/<номер>/<номер>.docx` и `<корень>/<номер>/photos/<тип>_<uuid>.<расширение>`. Номер — `protocol_number` (через API не меняется); если его нет — id с ведущими нулями до 5 цифр.
  - В БД: у протокола поле `files_location` (`in_progress` / `completed`), у фото `file_path` относительно корня (`00001/photos/...`). При переносе меняется только `files_location`.
  - Утверждение: сначала переносим папку в «Завершённые», потом сохраняем статус; если сохранить статус не удалось, возвращаем папку назад. Если папка с таким номером уже есть в «Завершённых», ошибка без слияния.
  - Возврат утверждённого оператору — папка возвращается в «В работе». Отмена — папка остаётся в «В работе». Удаление протокола — папка удаляется. Очистка в админке удаляет только папки протоколов из БД.
  - Папка протокола создаётся сразу при создании протокола.
  - DOCX: кнопка «Сохранить DOCX» только сохраняет файл в папку протокола (в браузер не скачивается) и показывает путь. При каждом нажатии `<номер>.docx` перезаписывается, копий нет. Сначала собираем во временный файл, потом подменяем старый. Если файл открыт в Word, отвечаем понятной ошибкой «файл занят», а не 500.
  - Фото отдаются через защищённый адрес `/cars/protocol-photos/<id>/file/` (работает и при `DEBUG=false`). Frontend грузит их через `api` в blob, потому что `<img>` не умеет отправлять JWT.
  - Команда `relocate_protocol_files [--dry-run]` переносит старые фото из `media/protocol_photos` и годится для переезда после смены путей. В конце выводит список фото, которых нет на диске.
- **Готово, когда:** пути задаются в админке; новые фото и DOCX попадают в «В работе/<номер>»; при утверждении папка переносится в «Завершённые», при возврате — назад; фото открываются на сайте в любом статусе и при `DEBUG=false`; в папке всегда один DOCX; старые фото перенесены командой.
- **Проверка:**
  - backend-тесты на временных папках (`override_settings` и временные пути в настройках): загрузка фото, утверждение и возврат с переносом, откат статуса, если перенос сорвался, проверка путей в админке, команда с `--dry-run` и без. Генерацию DOCX в тестах подменяем заглушкой (для Word нужен Windows с Office);
  - `manage.py check`, `manage.py test cars`, `npm run lint`, `npm run build`;
  - вручную: задать две папки в админке, провести протокол до утверждения, проверить папки, DOCX и фото на сайте; вернуть протокол оператору и проверить обратный перенос.
- **Заметки:** у учётной записи, под которой работает Django, должен быть доступ на запись в обе папки. Суперпользователь может редактировать утверждённый протокол — его фото тогда пишутся прямо в «Завершённые».
